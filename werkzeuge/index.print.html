Python & Thonny

Thonny ist die Python-Entwicklungsumgebung des Kurses. Sie bringt Python mit, hat eine eingebaute Shell, einen Debugger für Anfänger:innen und kann später direkt mit MicroPython-Boards sprechen. Ein Werkzeug für das ganze Jahr.

Installation

​
  1. Installer von thonny.org laden (Button „Windows“).
  2. Installer ausführen, Standardeinstellungen belassen. Python ist enthalten, es muss nichts extra installiert werden.
  3. Thonny aus dem Startmenü starten.

Auf Schul-PCs ist Thonny bereits installiert; falls nicht, gibt es auf thonny.org auch eine portable Version, die ohne Installationsrechte aus einem Ordner oder USB-Stick läuft.

  1. Auf thonny.org den Mac-Download wählen (Apple Silicon oder Intel, je nach Gerät).
  2. Die .pkg-Datei öffnen und den Anweisungen folgen.
  3. Thonny aus dem Programme-Ordner starten. Beim ersten Start eventuell Rechtsklick → Öffnen, falls macOS die Herkunft prüft.

Am einfachsten über die Paketverwaltung:

sudo apt install thonny      # Debian / Ubuntu / Mint / Pop!_OS

Alternativ das Installationsskript von thonny.org verwenden.

Wenn nichts installiert werden kann:

  • python.microbit.org — Python-Editor mit micro:bit-Simulator, läuft komplett im Browser.
  • Wokwi — Simulator für Pico, ESP32 und mehr, siehe Wokwi & Browser-Simulatoren.

Für reines PC-Python ohne Board funktioniert jeder Online-Python-Editor, der input() unterstützt.

Erster Start

  1. Beim ersten Start fragt Thonny nach Sprache: Deutsch wählen (später änderbar unter Werkzeuge → Optionen → Allgemein).
  2. Oben ist der Editor (hier schreibst du Programme), unten die Shell (hier probierst du einzelne Befehle).
  3. In die Shell tippen und Enter drücken:
print("Hallo Maker-Reise!")
  1. Ein Programm: Datei → Neu, Code eintippen, Datei → Speichern als test.py, dann grüner Play-Button (oder F5).

MicroPython-Boards (micro:bit, Pico, ESP32, Arduino)

MicroPython ist Python für kleine Computer ohne Bildschirm und Tastatur, sogenannte Mikrocontroller. Du schreibst denselben Python-Code wie am PC (if, while, Funktionen, Listen), dazu kommen Module wie machine oder microbit, mit denen du Pins, LEDs und Sensoren ansprichst. Programmiert wird in Thonny, das Board hängt per USB am PC.

Diese Seite brauchst du ab P1 Woche 3. Kein Board zur Hand? Derselbe Code läuft im Wokwi-Simulator.

Welches Board habe ich?

Welche Stärken die Boards haben, steht in Woche 2.

Was du brauchst

  • Ein USB-Datenkabel. Viele Kabel aus Handy-Ladegeräten können nur laden, keine Daten übertragen. Wird das Board nicht erkannt, ist das die häufigste Ursache. Markiere funktionierende Kabel mit Klebeband.
  • Für Pico, ESP32 und Nano ESP32: ein Steckbrett (Breadboard), Steckkabel, LEDs, Widerstände 220 Ω und 10 kΩ, eine Taste.
  • Für micro:bit: nichts, alles Nötige ist eingebaut. Für eigene Bauteile Krokodilklemmen oder ein Edge-Connector-Breakout.

Teil 1 · MicroPython aufspielen und mit Thonny verbinden

Das musst du einmal pro Board machen. Danach genügt: Board anstecken, Thonny starten.

​

Mit Thonny:

  1. micro:bit per USB anschließen. Am PC erscheint ein Laufwerk MICROBIT.
  2. Thonny: Werkzeuge → Optionen → Interpreter → MicroPython (BBC micro:bit).
  3. Unten rechts Install or update MicroPython klicken, das Laufwerk MICROBIT wählen, Install. Die gelbe LED auf der Rückseite blinkt, dann startet das Board neu.
  4. OK. In der Shell erscheint >>>. Test:
from microbit import *
display.scroll("Hallo")

Ohne Installation (Browser): python.microbit.org öffnen, Code schreiben, mit Send to micro:bit übertragen (Chrome oder Edge, verbindet sich direkt über USB). In anderen Browsern Save klicken und die .hex-Datei auf das Laufwerk MICROBIT ziehen. Der Editor hat einen eingebauten Simulator, siehe Wokwi & Browser-Simulatoren.

  1. Taste BOOTSEL gedrückt halten, dann das USB-Kabel einstecken, dann loslassen. Am PC erscheint ein Laufwerk RPI-RP2 (Pico 2: RP2350).
  2. Thonny: Werkzeuge → Optionen → Interpreter → MicroPython (Raspberry Pi Pico).
  3. Unten rechts Install or update MicroPython klicken.
  4. Target volume: das Laufwerk RPI-RP2. Variant: genau dein Modell wählen: Pico / Pico H, Pico W / Pico WH, Pico 2 oder Pico 2 W. Die falsche Variante läuft, aber ohne WLAN oder gar nicht.
  5. Install. Nach dem Kopieren verschwindet das Laufwerk, das Board startet neu.
  6. Fenster schließen, OK. In der Shell erscheint >>>. Test:
from machine import Pin
Pin("LED", Pin.OUT).value(1)    # Onboard-LED leuchtet

Treiber sind unter Windows 10/11, macOS und Linux nicht nötig.

  1. ESP32 per USB anschließen.
  2. Treiber prüfen (nur Windows, nur beim ersten Mal): Im Geräte-Manager unter Anschlüsse (COM & LPT) muss ein neuer COM-Port erscheinen. Fehlt er, auf den kleinen Chip neben der USB-Buchse schauen und den Treiber installieren:
    • Aufdruck CP210x (Silicon Labs) → CP210x-Treiber
    • Aufdruck CH340 / CH9102 (WCH) → CH340-Treiber
  3. Thonny: Werkzeuge → Optionen → Interpreter → MicroPython (ESP32), bei Port den neuen Port wählen (COM3, /dev/ttyUSB0, /dev/cu.usbserial-…).
  4. Unten rechts Install or update MicroPython (esptool) klicken.
  5. Target port: dein Port. MicroPython family: ESP32. Variant: Espressif • ESP32 / WROOM. Hast du ein ESP32-S3 oder C3, die passende Familie wählen.
  6. Install. Bleibt es bei Connecting... hängen: Taste BOOT gedrückt halten, bis Prozentzahlen erscheinen.
  7. Fenster schließen, OK. In der Shell erscheint >>>. Test:
from machine import Pin
Pin(2, Pin.OUT).value(1)        # Onboard-LED (bei den meisten DevKits)

Arduino UNO R3 und UNO R4: Für diese Boards gibt es kein offizielles MicroPython. Der Kurs ist in Python, darum gibt es zwei Wege:

  1. Simulator: In Wokwi ein ESP32-Projekt anlegen und den ESP32-Code des Kurses verwenden. Das ist gleichwertig: Ihr baut dieselbe Schaltung virtuell auf.
  2. Board tauschen: ESP32, Pico oder Arduino Nano ESP32 bei der Lehrkraft holen.

Arduino Nano ESP32:

  1. Arduino MicroPython Installer laden und starten.
  2. Nano ESP32 anschließen. Erkennt der Installer das Board nicht: Reset-Taste zweimal schnell hintereinander drücken.
  3. Board auswählen, Install MicroPython.
  4. Thonny: Werkzeuge → Optionen → Interpreter → MicroPython (ESP32), Port wählen, OK. Test:
from machine import Pin
Pin(48, Pin.OUT).value(1)       # Onboard-LED (D13)

Code wie im ESP32-Tab, aber mit anderen Pinnummern, siehe Teil 3.

Teil 2 · Arbeiten mit dem Board in Thonny

Sobald Thonny mit dem Board verbunden ist, gilt:

  • Die Shell spricht mit dem Board. print(1 + 1) rechnet der Mikrocontroller.
  • ▶ Play (F5) schickt die Datei im Editor zum Board und führt sie dort aus. Sie wird dabei nicht gespeichert: Nach dem Abstecken ist sie weg.
  • ■ Stopp (oder Strg+C in der Shell) bricht das Programm ab. Ein zweiter Klick auf Stopp startet das Board neu (Soft-Reset).

Dateien auf dem Board

Ansicht → Dateien zeigt oben die Dateien auf deinem PC, unten (Überschrift MicroPython device) die Dateien auf dem Board.

Eigene Module wie hardware.py (ab Woche 4) müssen auf dem Board liegen, damit import hardware funktioniert.

Der Code gehört ins Repository, nicht nur aufs Board

Das Board ist kein Speicherort. Speichere jede Datei auch auf dem PC und lade sie ins Team-Repository hoch. Ein Board kann verloren gehen, getauscht oder neu bespielt werden.

Teil 3 · Pinbelegung und Kurs-Verkabelung

Alle Programme im Kurs verwenden dieselbe Verkabelung pro Board. Halte dich daran, dann laufen die Beispiele ohne Änderung.

Strom aus beim Stecken
  • Bauteile nur stecken oder umstecken, wenn das USB-Kabel abgezogen ist.
  • Alle Boards arbeiten mit 3,3 V. Niemals 5 V an einen Eingangspin legen.
  • LEDs immer mit Vorwiderstand (220 Ω). Das lange Bein der LED zeigt zum Pin, das kurze zu GND.
  • 3V3 und GND nie direkt verbinden (Kurzschluss).
​

Für P1 ist nichts zu verkabeln: Tasten A/B, 5×5-Anzeige, Lichtsensor (die Anzeige selbst), Beschleunigungssensor, Temperatur, Mikrofon und Lautsprecher (V2) sind eingebaut.

Kurs-Funktionmicro:bit
Tastebutton_a, button_b
LEDPixel auf display
Summereingebauter Lautsprecher, music.pitch(...)
Lichtsensordisplay.read_light_level() (0–255)
Lageaccelerometer.get_x()

Eigene Bauteile schließt du mit Krokodilklemmen an die großen Ringe 0, 1, 2, 3V und GND an:

from microbit import *

pin0.write_digital(1)        # externe LED an Pin 0 (mit 220 Ω) ein
wert = pin1.read_analog()    # Analogwert an Pin 1, 0–1023
print(wert)

Die kleinen Pins am Rand erreichst du nur mit einem Breakout-Board. Viele davon gehören zur LED-Anzeige. Bleib bei 0, 1 und 2.

Achtung: Die Zahl im Code ist die GP-Nummer, nicht die Nummer des Beinchens. Pin(15) ist GP15, das ist Beinchen 20.

Analoge Eingänge gibt es nur an GP26, GP27 und GP28. Offizielles Pinout zum Ausdrucken: Pico, Pico W.

Das Steckbrett: Die Pico sitzt über der Mittelrille, jede Fünferreihe neben einem Beinchen ist mit diesem verbunden. Die langen Leisten am Rand (rot/blau) eignen sich für 3V3 und GND.

Gilt für das verbreitete ESP32-DevKit (30 oder 38 Pins). Die Zahl im Code ist die GPIO-Nummer, auf dem Board meist als D18, G18, IO18 oder nur 18 aufgedruckt.

Taste richtig stecken

Eine Taste mit vier Beinchen verbindet immer zwei Paare. Sicher funktioniert es, wenn du zwei diagonal gegenüberliegende Beinchen verwendest. Die Taste sitzt über der Mittelrille des Steckbretts.

Bewegungsmelder (PIR)

Der PIR liefert 1, solange er Bewegung erkennt. Mit den zwei Drehreglern stellst du Empfindlichkeit und Haltezeit ein. Nach dem Einschalten braucht er etwa eine Minute zum Kalibrieren.

from machine import Pin

_pir = Pin(17, Pin.IN)


def bewegung():
    """True, solange Bewegung erkannt wird."""
    return _pir.value() == 1
Ultraschall-Abstandssensor (HC-SR04)
from machine import Pin, time_pulse_us
import time

_trig = Pin(18, Pin.OUT)
_echo = Pin(19, Pin.IN)


def abstand_cm():
    """Abstand in cm, oder -1 wenn nichts gemessen wurde."""
    _trig.value(0)
    time.sleep_us(2)
    _trig.value(1)
    time.sleep_us(10)
    _trig.value(0)
    dauer = time_pulse_us(_echo, 1, 30000)   # höchstens 30 ms warten
    if dauer < 0:
        return -1
    return dauer * 0.0343 / 2                 # Schall: 343 m/s, hin und zurück
Servo (SG90)

Braun = GND, Rot = 5 V, Orange = Signal. Ein Servo zieht viel Strom: Startet das Board neu, sobald sich der Servo bewegt, reicht die USB-Versorgung nicht. Dann den Servo über eine eigene Stromquelle versorgen (GND verbinden).

from machine import Pin, PWM

_servo = PWM(Pin(20))
_servo.freq(50)


def servo(winkel):
    """Dreht den Servo auf 0–180 Grad."""
    # 0,5 ms (0°) bis 2,5 ms (180°) von 20 ms
    _servo.duty_u16(1638 + winkel * (8192 - 1638) // 180)
Temperatur und Luftfeuchte (DHT11 / DHT22)

Das Modul dht ist bei Pico und ESP32 schon dabei. Der Sensor darf höchstens einmal pro Sekunde (DHT22: alle 2 s) abgefragt werden.

from machine import Pin
import dht

_dht = dht.DHT11(Pin(21))      # beim DHT22: dht.DHT22(...)


def temperatur():
    _dht.measure()
    return _dht.temperature()   # °C


def feuchte():
    _dht.measure()
    return _dht.humidity()      # %
OLED-Display (SSD1306, 128×64, I²C)

Den Treiber einmal aufs Board installieren: Thonny Werkzeuge → Verwalte Pakete …, nach ssd1306 suchen, Installieren.

from machine import Pin, I2C
import ssd1306

_i2c = I2C(0, sda=Pin(4), scl=Pin(5))     # ESP32: I2C(0, sda=Pin(21), scl=Pin(22))
_oled = ssd1306.SSD1306_I2C(128, 64, _i2c)


def anzeigen_text(zeile1, zeile2=""):
    _oled.fill(0)
    _oled.text(zeile1, 0, 0)
    _oled.text(zeile2, 0, 16)
    _oled.show()

Meldet I2C(...) einen Fehler oder bleibt das Display dunkel: print(_i2c.scan()) muss [60] ausgeben. Eine leere Liste heißt: SDA/SCL vertauscht oder nicht verbunden.

Wokwi & Browser-Simulatoren

Ein Simulator zeigt im Browser ein virtuelles Board mit LEDs, Tasten und Sensoren. Dein MicroPython-Code läuft darin genauso wie auf dem echten Board. Du brauchst nichts zu installieren, nur einen Browser.

SimulatorBoardsWofür
WokwiRaspberry Pi Pico, ESP32eigene Schaltungen mit Steckbrett-Bauteilen, hardware.py, später WLAN (P2)
python.microbit.orgmicro:bitEditor und Simulator in einem, Sensoren per Schieberegler

Wann simulieren?

Der Simulator ist kein Notbehelf, sondern ein gleichwertiges Werkzeug:

  • Kein Board da: zu Hause, bei Krankheit, wenn das Team-Board gerade bei jemand anderem liegt.
  • Arduino UNO R3 / R4: Diese Boards können kein MicroPython. Euer Team baut die Schaltung in Wokwi mit einem ESP32 auf (siehe MicroPython-Boards).
  • Vor dem Verkabeln: Schaltung erst virtuell aufbauen und testen. Was im Simulator nicht geht, geht auf dem Steckbrett auch nicht.
  • Zum Teilen: Ein Wokwi-Link zeigt Code und Schaltung. Ideal fürs Team-Repository und für Fragen an die Lehrkraft.

Fehler in diagram.json

Jeder Eintrag endet mit einem Komma, außer dem letzten in der Liste. War die Liste vorher leer ([]), lösch das Komma nach der letzten eingefügten Zeile. Wokwi unterstreicht Fehler rot. Heißt das Board in deiner Datei nicht pico bzw. esp (siehe "id" beim Board-Eintrag), ersetze den Namen in den Verbindungen.

Lichtsensor statt Potentiometer

Wokwi hat ein Lichtsensor-Modul (Photoresistor sensor, Anschlüsse VCC → 3V3, GND → GND, AO → GP26 bzw. GPIO 34). Achtung: Bei diesem Modul sinkt der Wert, wenn es heller wird, also genau umgekehrt wie bei der Kurs-Schaltung. In hardware.py dann 100 - … rechnen:

def helligkeit():
    return 100 - _sensor.read_u16() * 100 // 65535

Für den Kurs ist das Potentiometer einfacher: drehen = heller/dunkler.

Wer sieht mein Projekt?

micro:bit: python.microbit.org

Der micro:bit-Python-Editor hat den Simulator gleich eingebaut.

  1. python.microbit.org öffnen. Links Code schreiben.

Grenzen des Simulators

Ein Simulator ist ein Modell der Wirklichkeit. Einiges bildet er nicht ab:

Im SimulatorAuf dem echten Board

Teil 3 · Datei im Browser bearbeiten und committen

Diagramme mit Mermaid

Mermaid zeichnet Diagramme aus Text. Du beschreibst in ein paar Zeilen, welche Kästchen es gibt und welche Pfeile sie verbinden, und Mermaid macht daraus eine Grafik. Weil das Diagramm nur Text ist, steht es direkt in deiner Markdown-Datei, lässt sich mit Git versionieren und ist in Sekunden geändert. Kein Zeichenprogramm, kein Screenshot, der veraltet.

So schreibst du einen Mermaid-Block

Ein Mermaid-Diagramm ist ein Code-Block mit der Sprache mermaid:

```mermaid
flowchart LR
    A --> B
```

wird zu

flowchart LR
    A --> B

Die erste Zeile im Block sagt, welche Art von Diagramm du willst. Für dieses Buch brauchst du zwei: flowchart und stateDiagram-v2.

Wo wird Mermaid angezeigt?

GitHub und dieses Buch zeigen den Block als Grafik. Thonny und viele Editoren zeigen nur den Text. Zum Ausprobieren nimm den Online-Editor mermaid.live: links tippen, rechts sofort das Bild sehen.

Flussdiagramm: flowchart

Richtung

Gleich nach flowchart kommt die Richtung:

KürzelRichtung
LRvon links nach rechts
TDvon oben nach unten

Knoten

Jeder Knoten hat eine ID (kurz, ohne Leerzeichen und Umlaute) und eine Beschriftung. Die Klammern um die Beschriftung bestimmen die Form:

Du schreibstFormWofür
A[Text]RechteckSchritt, Bauteil
A([Text])abgerundetStart, Ende
A{Text}RauteEntscheidung, Frage
A((Text))Kreisdas Gerät selbst

Hast du einen Knoten einmal beschriftet, reicht danach die ID.

Pfeile

Du schreibstBedeutung
A --> BPfeil
A -->|ja| BPfeil mit Beschriftung
A --- BLinie ohne Spitze

So skizziert ihr in Woche 2 euer Gadget:

Wenn das Diagramm nicht erscheint

Mermaid ist streng: Ein einziger Tippfehler, und statt der Grafik kommt eine Fehlermeldung oder gar nichts. Prüfe der Reihe nach:

  • Beginnt der Block mit ```mermaid (klein geschrieben) und endet er mit ```?
  • Stimmt die erste Zeile genau: flowchart LR, flowchart TD oder stateDiagram-v2?
  • Sind die IDs ohne Leerzeichen, Umlaute und Sonderzeichen? LED_AN geht, LED an nicht.
  • Enthält eine Beschriftung Klammern oder Anführungszeichen? Dann setze sie in Anführungszeichen: A["Taste (rot)"].
  • Heißt ein Knoten im Flussdiagramm end? Das ist ein reserviertes Wort. Nimm Ende oder E([Ende]).
  • Pfeil richtig geschrieben? Es sind zwei Striche: -->.
Erst Papier, dann Mermaid

Überleg dir das Diagramm zuerst mit Stift und Papier. Mermaid ist zum sauberen Abschreiben da, nicht zum Nachdenken. Wenn es in mermaid.live funktioniert, kopierst du den Block in deine .md-Datei.
