Subsections of Tools

Python & Thonny

Thonny is the Python development environment of this course. It ships with Python, has a built-in shell, a beginner-friendly debugger and can later talk directly to MicroPython boards. One tool for the whole year.

Installation

​
  1. Download the installer from thonny.org (button “Windows”).
  2. Run the installer, keep the default settings. Python is included, nothing else needs to be installed.
  3. Start Thonny from the start menu.

On school PCs Thonny is already installed; if not, thonny.org also offers a portable version that runs from a folder or USB stick without install rights.

  1. On thonny.org choose the Mac download (Apple Silicon or Intel, depending on your device).
  2. Open the .pkg file and follow the instructions.
  3. Start Thonny from the Applications folder. On first start you may need right-click → Open if macOS checks the origin.

Easiest via the package manager:

sudo apt install thonny      # Debian / Ubuntu / Mint / Pop!_OS

Alternatively use the install script from thonny.org.

If nothing can be installed:

  • python.microbit.org — Python editor with micro:bit simulator, runs entirely in the browser.
  • Wokwi — simulator for Pico, ESP32 and more, see Wokwi & Browser Simulators.

For plain PC Python without a board, any online Python editor that supports input() works.

First start

  1. On first start Thonny asks for a language: pick yours (changeable later under Tools → Options → General).
  2. The top is the editor (where you write programs), the bottom is the shell (where you try single commands).
  3. Type into the shell and press Enter:
print("Hello Maker Journey!")
  1. A program: File → New, type the code, File → Save as test.py, then the green play button (or F5).

MicroPython Boards (micro:bit, Pico, ESP32, Arduino)

MicroPython is Python for small computers without screen or keyboard, so-called microcontrollers. You write the same Python code as on the PC (if, while, functions, lists), plus modules such as machine or microbit that control pins, LEDs and sensors. You program in Thonny, the board is connected to the PC via USB.

You need this page from P1 week 3. No board at hand? The same code runs in the Wokwi simulator.

Which board do I have?

BoardHow to recognise itMicroPython?
micro:bitPocket-sized, 5×5 LED display, buttons A and B. V2 has a golden touch logo and a speaker on the back.yes
Raspberry Pi PicoGreen strip, printed “Raspberry Pi Pico” (Pico W / Pico 2 W with a silver Wi-Fi chip cover), button BOOTSEL.yes
ESP32Usually a black board with a silver metal cover “ESP32-WROOM”, two buttons EN and BOOT. Many manufacturers, pins labelled differently.yes
Arduino Nano ESP32Small Arduino board, printed “Nano ESP32”.yes
Arduino UNO R3 / UNO R4Large Arduino board with header sockets.no, see tab “Arduino”

The strengths of each board are listed in week 2.

What you need

  • A USB data cable. Many cables from phone chargers can only charge, not transfer data. If the board is not detected, this is the most common cause. Mark working cables with tape.
  • For Pico, ESP32 and Nano ESP32: a breadboard, jumper wires, LEDs, resistors 220 Ω and 10 kΩ, a push button.
  • For micro:bit: nothing, everything you need is built in. For your own components: crocodile clips or an edge connector breakout.

Part 1 · Install MicroPython and connect Thonny

You do this once per board. Afterwards: plug in the board, start Thonny.

​

With Thonny:

  1. Connect the micro:bit via USB. A drive MICROBIT appears on the PC.
  2. Thonny: Tools → Options → Interpreter → MicroPython (BBC micro:bit).
  3. Click Install or update MicroPython at the bottom right, choose the MICROBIT drive, Install. The yellow LED on the back flashes, then the board restarts.
  4. OK. The shell shows >>>. Test:
from microbit import *
display.scroll("Hello")

Without installing anything (browser): open python.microbit.org, write code, transfer it with Send to micro:bit (Chrome or Edge, connects directly via USB). In other browsers click Save and drag the .hex file onto the MICROBIT drive. The editor has a built-in simulator, see Wokwi & Browser Simulators.

  1. Hold the BOOTSEL button, then plug in the USB cable, then release. A drive RPI-RP2 (Pico 2: RP2350) appears on the PC.
  2. Thonny: Tools → Options → Interpreter → MicroPython (Raspberry Pi Pico).
  3. Click Install or update MicroPython at the bottom right.
  4. Target volume: the RPI-RP2 drive. Variant: pick exactly your model: Pico / Pico H, Pico W / Pico WH, Pico 2 or Pico 2 W. The wrong variant runs without Wi-Fi or not at all.
  5. Install. After copying, the drive disappears and the board restarts.
  6. Close the window, OK. The shell shows >>>. Test:
from machine import Pin
Pin("LED", Pin.OUT).value(1)    # onboard LED lights up

No drivers are needed on Windows 10/11, macOS and Linux.

  1. Connect the ESP32 via USB.
  2. Check the driver (Windows only, first time only): In Device Manager under Ports (COM & LPT) a new COM port must appear. If it is missing, look at the small chip next to the USB socket and install the driver:
    • printed CP210x (Silicon Labs) → CP210x driver
    • printed CH340 / CH9102 (WCH) → CH340 driver
  3. Thonny: Tools → Options → Interpreter → MicroPython (ESP32), under Port choose the new port (COM3, /dev/ttyUSB0, /dev/cu.usbserial-…).
  4. Click Install or update MicroPython (esptool) at the bottom right.
  5. Target port: your port. MicroPython family: ESP32. Variant: Espressif • ESP32 / WROOM. If you have an ESP32-S3 or C3, choose the matching family.
  6. Install. If it hangs at Connecting...: hold the BOOT button until percentages appear.
  7. Close the window, OK. The shell shows >>>. Test:

Pin(2, Pin.OUT).value(1)        # onboard LED (on most DevKits)

  1. Simulator: create an ESP32 project in Wokwi and use the course’s ESP32 code. This is equivalent: you build the same circuit virtually.
  2. Swap the board: get an ESP32, Pico or Arduino Nano ESP32 from your teacher.

Arduino Nano ESP32:

  1. Download and start the Arduino MicroPython Installer.
  2. Connect the Nano ESP32. If the installer does not detect the board: press the reset button twice quickly.
  3. Select the board, Install MicroPython.

Part 2 · Working with the board in Thonny

As soon as Thonny is connected to the board:

  • The shell talks to the board. print(1 + 1) is computed by the microcontroller.
  • ▶ Play (F5) sends the file in the editor to the board and runs it there. It is not saved: after unplugging it is gone.
  • ■ Stop (or Ctrl+C in the shell) aborts the program. A second click on Stop restarts the board (soft reset).

Part 3 · Pinout and course wiring

All programs in the course use the same wiring per board. Stick to it and the examples run without changes.

Power off while wiring
  • Only plug in or move components when the USB cable is unplugged.
  • All boards work with 3.3 V. Never connect 5 V to an input pin.
  • Always use a series resistor (220 Ω) with LEDs. The long leg of the LED goes towards the pin, the short one to GND.
  • Never connect 3V3 and GND directly (short circuit).
​

For P1 there is nothing to wire: buttons A/B, 5×5 display, light sensor (the display itself), accelerometer, temperature, microphone and speaker (V2) are built in.

Your own components connect with crocodile clips to the large rings 0, 1, 2, 3V and GND:

from microbit import *

pin0.write_digital(1)        # external LED on pin 0 (with 220 Ω) on
value = pin1.read_analog()   # analog value on pin 1, 0–1023
print(value)

The small pins along the edge are only reachable with a breakout board. Many of them belong to the LED display. Stick to 0, 1 and 2.

Careful: the number in the code is the GP number, not the number of the physical pin. Pin(15) is GP15, which is physical pin 20.

The breadboard: the Pico sits across the centre groove, each row of five next to a pin is connected to it. The long rails along the edge (red/blue) are handy for 3V3 and GND.

Placing the button correctly

A four-legged push button always connects two pairs. It works reliably if you use two diagonally opposite legs. The button sits across the centre groove of the breadboard.

5 V is available on pin VBUS (Pico, pin 40), 5V/VIN (ESP32) or VBUS (Nano ESP32) while the board is powered via USB.

The examples below use the Pico pins. For other boards insert the number from the table. On the micro:bit most of these components are awkward (few pins, no 5 V). Use the built-in sensors there instead.

Motion sensor (PIR)

The PIR returns 1 as long as it detects motion. The two knobs set sensitivity and hold time. After power-on it needs about a minute to calibrate.

from machine import Pin

_pir = Pin(17, Pin.IN)


def motion():
    """True as long as motion is detected."""
    return _pir.value() == 1
Ultrasonic distance sensor (HC-SR04)
from machine import Pin, time_pulse_us
import time

_trig = Pin(18, Pin.OUT)
_echo = Pin(19, Pin.IN)


def distance_cm():
    """Distance in cm, or -1 if nothing was measured."""
    _trig.value(0)
    time.sleep_us(2)
    _trig.value(1)
    time.sleep_us(10)
    _trig.value(0)
    duration = time_pulse_us(_echo, 1, 30000)   # wait at most 30 ms
    if duration < 0:
        return -1
    return duration * 0.0343 / 2                 # sound: 343 m/s, there and back
Servo (SG90)

Brown = GND, red = 5 V, orange = signal. A servo draws a lot of current: if the board restarts as soon as the servo moves, USB power is not enough. Then power the servo from a separate source (connect the GNDs).

from machine import Pin, PWM

_servo = PWM(Pin(20))
_servo.freq(50)


def servo(angle):
    """Turns the servo to 0–180 degrees."""
    # 0.5 ms (0°) to 2.5 ms (180°) out of 20 ms
    _servo.duty_u16(1638 + angle * (8192 - 1638) // 180)
Temperature and humidity (DHT11 / DHT22)

The dht module is already included on Pico and ESP32. The sensor may be read at most once per second (DHT22: every 2 s).

from machine import Pin
import dht

_dht = dht.DHT11(Pin(21))      # for DHT22: dht.DHT22(...)


def temperature():
    _dht.measure()
    return _dht.temperature()   # °C


def humidity():
    _dht.measure()
    return _dht.humidity()      # %
OLED display (SSD1306, 128×64, I²C)

Install the driver on the board once: Thonny Tools → Manage packages, search for ssd1306, Install.

from machine import Pin, I2C
import ssd1306

_i2c = I2C(0, sda=Pin(4), scl=Pin(5))     # ESP32: I2C(0, sda=Pin(21), scl=Pin(22))
_oled = ssd1306.SSD1306_I2C(128, 64, _i2c)


def show_text(line1, line2=""):
    _oled.fill(0)
    _oled.text(line1, 0, 0)
    _oled.text(line2, 0, 16)
    _oled.show()

If I2C(...) reports an error or the display stays dark: print(_i2c.scan()) must print [60]. An empty list means SDA/SCL are swapped or not connected.

Wokwi & Browser Simulators

A simulator shows a virtual board with LEDs, buttons and sensors in the browser. Your MicroPython code runs in it just like on the real board. You don’t need to install anything, only a browser.

SimulatorBoardsUsed for
WokwiRaspberry Pi Pico, ESP32your own circuits with breadboard components, hardware.py, later Wi-Fi (P2)
python.microbit.orgmicro:biteditor and simulator in one, sensors via sliders

When to simulate?

The simulator is not a stopgap but an equivalent tool:

  • No board available: at home, when ill, when the team board is with someone else.
  • Arduino UNO R3 / R4: these boards cannot run MicroPython. Your team builds the circuit in Wokwi with an ESP32 (see MicroPython Boards).
  • Before wiring: build and test the circuit virtually first. What does not work in the simulator will not work on the breadboard either.
  • For sharing: a Wokwi link shows code and circuit. Ideal for the team repository and for questions to your teacher.

Errors in diagram.json

Every entry ends with a comma, except the last one in the list. If the list was empty before ([]), delete the comma after the last inserted line. Wokwi underlines errors in red. If the board in your file is not called pico or esp (see "id" in the board’s entry), replace the name in the connections.

Light sensor instead of potentiometer

Wokwi has a light sensor module (Photoresistor sensor, pins VCC → 3V3, GND → GND, AO → GP26 or GPIO 34). Careful: with this module the value drops when it gets brighter, exactly the opposite of the course circuit. Then calculate 100 - … in hardware.py:

def brightness():
    return 100 - _sensor.read_u16() * 100 // 65535

For the course the potentiometer is simpler: turn it = brighter/darker.

Limits of the simulator

A simulator is a model of reality. Some things it does not reproduce:

In the simulatorOn the real board
sensors deliver exact, steady valuesvalues fluctuate, check thresholds again on the board
a reversed LED simply does not lightsame, but a short circuit can destroy components
power is unlimitedservos and motors can make the board restart
timing roughly realisticreaction games and tone lengths may feel slightly different
Wi-Fi via the network Wokwi-GUEST (no password, ESP32 and Pico W only)real school Wi-Fi, see P2

So the rule is: develop in the simulator, final check on the board. Arduino teams demo their gadget in Wokwi at the review.

Diagrams with Mermaid

Mermaid draws diagrams from text. You describe in a few lines which boxes there are and which arrows connect them, and Mermaid turns that into a picture. Because the diagram is just text, it lives right inside your Markdown file, can be versioned with Git and is changed in seconds. No drawing program, no screenshot that goes out of date.

How to write a Mermaid block

A Mermaid diagram is a code block with the language mermaid:

```mermaid
flowchart LR
    A --> B
```

becomes

flowchart LR
    A --> B

The first line in the block says which kind of diagram you want. For this book you need two: flowchart and stateDiagram-v2.

Where is Mermaid displayed?

GitHub and this book show the block as a picture. Thonny and many editors only show the text. To try things out, use the online editor mermaid.live: type on the left, see the picture on the right straight away.

Flowchart: flowchart

Direction

Right after flowchart comes the direction:

CodeDirection
LRleft to right
TDtop to bottom

Nodes

Every node has an ID (short, no spaces or special characters) and a label. The brackets around the label decide the shape:

You writeShapeUsed for
A[Text]rectanglestep, component
A([Text])roundedstart, end
A{Text}diamonddecision, question
A((Text))circlethe device itself

Once a node has a label, the ID alone is enough after that.

Arrows

You writeMeaning
A --> Barrow
A -->|yes| Barrow with a label
A --- Bline without a tip

This is how you sketch your gadget in week 2:

    G --> LED[LED]

Example 2: flowchart with a decision

With a diamond and labelled arrows you draw an if:

```mermaid
    ON --> W[wait briefly]
    OFF --> W
    W --> M
```

The arrow from W back to M is the while True loop.

State diagram: stateDiagram-v2

A state diagram shows which states a device can be in and which event takes it from one state to the next. More on this in week 4.

You writeMeaning
[*] --> OFFthe start state is OFF
OFF --> ON: buttontransition from OFF to ON on the event “button”
ON --> OFF: button / LED offevent / what happens along the way
OFF --> [*]end state (rarely needed)

You don’t have to declare states separately. As soon as a name appears in an arrow, it exists.

When the diagram doesn’t appear

Mermaid is strict: a single typo, and instead of the picture you get an error message or nothing at all. Check in this order:

  • Does the block start with ```mermaid (lower case) and end with ```?
  • Is the first line exactly flowchart LR, flowchart TD or stateDiagram-v2?
  • Are the IDs free of spaces and special characters? LED_ON works, LED on doesn’t.
  • Does a label contain brackets or quotes? Then put it in quotation marks: A["Button (red)"].
  • Is a flowchart node called end? That is a reserved word. Use End or E([End]).
  • Is the arrow written correctly? It has two dashes: -->.
Paper first, then Mermaid

Work out the diagram with pen and paper first. Mermaid is for writing it up neatly, not for thinking. Once it works in mermaid.live, copy the block into your .md file.
